WaveMaker announces the release of WaveMaker AI 12.0.0 — the first release of the WaveMaker AI line and a major step up from 11.15.x.

For the story behind the release, read [A New Era of AI-Accelerated Application Development](../the-announcement). For technology stack upgrades, refer to [Technology Stack](/tech-stack?v=12-0-0).

## 12.0.0

*Release date: 07 September 2026*

### Highlights

- **[WaveMaker Agent](../../../developing-with-agents/)** — prompt-driven agents for UI, backend, API integration, security, localization and screenshot-to-code, in a chat experience built into Studio.
- **[Design to Code](../../../design-system/figma-design-to-code-plugin/working-with-design-to-code-plugin)** — convert supported Figma designs into working WaveMaker projects, and sync new pages into projects you already have.
- **React** — React joins Angular as a web build target.

      * ### Design System projects for mobile <Pill type="mobile" />

        Design System projects, introduced for Web in 11.14.0, now cover mobile. Styling is driven by global and component-level design tokens instead of custom CSS, and components ship with standardized variants, so one design system spans your web and mobile apps.

        Existing mobile projects are not converted automatically.

        [Documentation](../../../design-system/concepts)

        Style Workspace, introduced for Web in 11.14.0, now supports mobile projects. This release also adds:

        - **Custom text font families**: upload `.ttf` fonts directly from Studio under the **Text** tab's **Font.Family** token, instead of copying files and hand-editing `font.config.js`. Uploads are grouped into families automatically, and **Font.Family** becomes a dropdown of the available weights and styles. This is separate from the icon font family import available since 11.5.0.
        - **Token usage highlighting**: see which components use a selected token.
        - **State tokens for list items**: default, hover and selected states.
        - **Templates for native mobile projects**, including a menu-dropdown template.

        [Style Workspace](../../../user-interfaces/web/develop/styling-with-design-tokens/working-with-style-workspace.mdx) · [Uploading custom fonts](../../../user-interfaces/mobile/develop/styling-with-design-tokens/uploading-custom-fonts)

      * ### Auto Layout on mobile, and fill sizing for child components <Pill type="web" /> <Pill type="mobile" />

        Auto Layout, introduced for Web containers in 11.14.0, now supports mobile projects.

        Sizing also supports `fill` (occupy the available space in the parent) on any component placed inside an Auto Layout container, not just on the containers themselves — alongside fixed values (px, %) and `hug` (size to content). Fill sizing for child components is currently available in Angular.

        [Documentation](../../../user-interfaces/web/develop/working-with-layouts/auto-layout)

      * ### React as a web build output <Pill type="web" />

        Export production-ready React code from the same visual development experience you already use, with no change to your markup or workflow. The React output includes:

        - **React output preview in Studio**: preview the generated React app without switching contexts.
        - **A dedicated service layer**: API and variable calls are exposed as typed service functions instead of being inlined into page components, so the generated code is easier to read, extend and hand off to developers.
        - **Web Components support**: embed third-party Web Components *into* generated pages — codegen wraps them automatically with a WebComponent helper. This is the inbound counterpart to exporting Prefabs as Web Components, available since 11.10.0.
        - **WMX components on Web**: WMX, available for React Native since 11.12.0, now works in React projects, with preview support in React Preview through a centralized preview model.

      * ### Charts on mobile powered by ECharts <Pill type="mobile" />

        Area, Bar, Column, Line, Bubble, Pie and Donut charts on mobile now render using [ECharts](https://github.com/wavemaker/wm-react-native-echarts) instead of Victory Native, giving smoother animations, richer tooltips and a more polished look with your existing markup.

      * ### Native SVG icons across web and mobile <Pill type="web" /> <Pill type="mobile" />

        SVG is now a first-class citizen across widgets on both platforms — mobile components including Menu, Switch and Tabbar render icons as SVGs rather than font icons, with no font-icon workarounds needed.

      * ### Offline support for mobile apps <Pill type="mobile" />

        Keep previously fetched data available when connectivity drops:

        - **Offline-aware caching for service variables**: a configurable cache interceptor stores GET responses in session or on-device persistent storage with a configurable TTL and automatic background cleanup of expired entries.
        - **Offline banner**: a styled banner appears when the device loses connectivity, controlled by the `showofflinebanner` page property.
        - **Pull-to-refresh**: Service, CRUD and Live variables support a `pulltorefreshUpdate` property.

      * ### Device-specific prefab rendering at design time <Pill type="web" /> <Pill type="mobile" />

        Prefab components configured to render based on device type or items-per-row now reflect that configuration at design time, not just at runtime.

      - ### WaveMaker Agent for application development

        Use WaveMaker Agent to build your application from prompts, with the most relevant sub-agents selected automatically for the task you describe. Coverage includes:

        - API integration and binding
        - Backend service and query creation
        - JavaScript generation
        - Security configuration
        - Localization
        - Screenshot-to-Code for web and mobile — for mobile, the agent resolves global design tokens and brand styling before generating screens from a Figma design or screenshot, and derives required-field rules from the design
        - Chart generation for mobile, covering all 8 chart types
        - Custom WMX web component creation, renaming and deletion for React

        [Documentation](../../../developing-with-agents/)

      - ### WaveMaker Agent chat in Studio

        A conversation-driven development experience built into Studio:

        - **Cancel a running conversation**, letting the agent finish what it is currently doing — generating a response, running a tool, or delegating to a sub-agent — before stopping.
        - **Edit a previously sent prompt** and resubmit it, replacing all messages, agent actions and file changes made after that point, along with any images or chat suggestions carried over from the original prompt.
        - **Restore to a checkpoint**, permanently removing all messages, agent interactions, tool executions and changes made after the selected point.
        - **Regenerate a previous run**, creating a new branch from that point without losing your prior work.
        - **Suggested next actions** at the end of a conversation, so you can continue a workflow without working out the next step yourself.
        - **Live context window usage** during a conversation, with automatic compaction of long conversation histories to keep responses fast and context relevant.
        - **App resource suggestions**: type to search and select variables, widgets and APIs directly in the chat panel.
        - **Draft review awareness**: the agent is told, at the start of its next run, about any accept, reject, edit or Studio-sync actions you took on its previous code changes.
        - **Studio change sync**: conversations reflect the most recent project changes made in Studio without starting a new session.
        - **Completion notifications**: a Studio toast and a blue-dot unread indicator when a conversation completes, plus a desktop notification that opens the conversation directly when you are away from the tab.
        - **Automatic recovery after a network interruption**, so a temporary drop no longer fails the conversation.
        - **Session import and export**: upload project resources into a session, and export a session — conversation history, uploaded files and session context — as a ZIP archive.
        - **Image support in file reads**: the file-reading tool reads image files and includes them as visual content in the conversation.

      - ### WaveMaker Agent chat rebuilt on the AG UI protocol <Pill type="web" />

        The WaveMaker Agent chat interface runs on the AG UI protocol, replacing Theia, for a more responsive and extensible experience. The agent server itself has been rewritten in Python, improving response performance and enabling deeper agent extensibility. The AG-UI WebSocket run API also accepts a per-request LLM model override (`llm_model_id` or `llm_config`), applied to the run and every delegated sub-agent.

      - ### Code Review agent

        A dedicated agent that audits your WaveMaker project files against best practices and surfaces violations as structured, actionable tables. It is report-only and never edits or rewrites your files. The agent currently specializes in HTML and CSS files.

      - ### Custom instructions via Agents.md <Pill type="web" /> <Pill type="mobile" />

        Add an `Agents.md` file to your project to provide custom instructions that WaveMaker Agent follows automatically when building the app.

      - ### AI Analytics in Team Portal

        A single AI Analytics page that gives Team Portal admins full visibility into WaveMaker Agent usage, cost and code-change acceptance across their team.

      - ### WaveMaker Agent restricted from Studio-managed files

        WaveMaker Agent is blocked from writing or editing gitignored, build-managed and other auto-generated files, preventing corruption of the project.

      - ### Automatic sensitive data redaction <Pill type="web" />

        Sensitive content in conversation context is redacted before being forwarded to sub-agents.

      - ### Core details and upgrade in Projects Hub

        Projects Hub shows Core details for an app, including the current Core version, an Upgrade Core dialog and a current-version badge. Core version information is also included in the linked implementation's branch naming and shown under the project name.

      - ### Search across project files in Studio

        Search for text across all project files from the File Explorer, with in-file result navigation, a dedicated search toggle, and clear no-results and start states.

        Tappable components automatically enforce the platform-recommended minimum touch target (44pt on iOS, 48dp on Android) when their visible size is smaller, improving usability and accessibility without changing how they look.         The API variable's loading spinner message can now be localized using a bind expression.

        Studio's loading screen now uses an animated Lottie-based loader instead of the previous static spinner, streamed from a CDN rather than bundled with the app.

        Renamed the **Design** tab to **Studio**, updated its icon, and added highlighting for the active tab.

    <Accordian title="Platform">
      - ### Improved i18n performance when localizing pages and adding new languages <Pill type="web" /> <Pill type="mobile" />

        - Adding a new label to a page no longer requires loading every message across all languages just to check for duplicates. The check is now quick and targeted, so localizing pages uses less context and completes faster, even in apps with thousands of messages.

        - Adding a new language to your app now avoids reloading existing content from scratch each time. It's loaded once and shared across every language you add, whether together or one after another, using far less context.

      - ### Section-level reads and edits for large project files

        Large files can now be read and edited in sections using offset and limit, instead of the whole file. Edits are checked only against that section, so unrelated changes elsewhere don't block them, giving faster edits with less token usage.

      - ### Faster previews <Pill type="web" /> <Pill type="mobile" />

        - **React Native**: preview builds no longer rerun `npm install` on unchanged projects, cutting unchanged build time from about 2m47s to 23s and removing intermittent out-of-memory and `esbuild not found` failures.
        - **Angular**: project preview no longer triggers an unnecessary Angular code-generation pass.

      - ### WaveMaker Agent chat experience improvements

        - Hover-highlighted suggestions and quick-access side popovers in the chat panel.
        - Typing `@` opens context suggestions directly, with grouped categories and improved filtering.
        - The subagent header shows a descriptive task title alongside the agent name, so it's easier to follow what each subagent is working on.
        - A redesigned changes section, with the total count of changed files in its header and clearer visibility of available updates.
        - Clearer agent activity and execution status indicators, including conversation execution time at the end of a completed conversation and clearer failed-status icons for sub-agents and tool calls.
        - Redesigned context compaction and context size UI.
        - Agent descriptions appear on hover during agent selection.
        - Edit confirmation now happens inline in the chat input instead of in a separate dialog.
        - A redesigned cancelled-conversation indicator, and a merge-conflicts banner restyled to match Studio.
        - The conversation panel auto-collapses and restores around the file editor, the editor refreshes automatically when new VCS changes arrive, and a success toaster confirms when Studio changes have synced to the conversation.
        - Updated icons, copy feedback and Studio-aligned notifications.

      - ### Improved agent orchestration and efficiency

        - Better orchestration between agents for tasks that span both UI and backend.
        - WaveMaker Agent handles small lookups directly and writes bulky results to files, instead of spawning background tasks or echoing full content as text.

      - ### More reliable WaveMaker Agent output for mobile <Pill type="mobile" />

        Improved WaveMaker Agent-authored React Native forms, containers, push notification handling and plugin version lookups.

      - ### Delete and rename WMX web components <Pill type="web" />

        WaveMaker Agent can now delete and rename React WMX web components, in addition to creating them.

      - ### Selective container patching in Instance Patch API

        The Instance Patch API now accepts a `patchComponents` parameter to update individual containers selectively without reloading the full instance.

        Fixed REST service calls failing with "Target port must not be negative" when the app proxy was configured with include/exclude URLs.

      - ### REST variable input fields lost on reopen

        Fixed a Web Service (REST) variable's configured input fields not showing when the variable was reopened.

      - ### CRUD endpoints not selectable for API variable

        Fixed being unable to select CRUD endpoints while creating an API variable.

      - ### API-aware live variable initialised with empty filterExpressions

        Fixed `createApiAwareVariable` setting `filterExpressions` to `{}` on a live variable, which caused a downstream validation error.

        Fixed a success or error callback sometimes being added to the page script but not saved to `variables.json` when added to an existing variable.

      - ### Custom formatter code generated in app.js instead of formatters.js

        Fixed custom formatter code being written to `app.js` instead of the correct `formatters.js` file.

        - Fixed the chat being unable to reliably match a compaction or cancel indicator's start to its own completion when more than one occurred in the same run.
        - Fixed internal compaction text leaking into a background task's visible output, and its status indicator appearing outside that task's own card.

        - Fixed incorrect restore behavior and failed base lookups after combinations of accepting, rejecting and syncing draft changes with Studio, by tracking each action with its own marker instead of a single shared pointer.

        - Fixed WaveMaker Agent not reliably loading the skills it depends on before performing a task, leading to avoidable errors or incorrect first attempts.
